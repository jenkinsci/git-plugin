Every build records which commit was last built on each branch, and copies that history from the previous build. When a job builds many different branches over time, for example one merge request branch per build through a parameterized branch specifier, the history grows with every branch ever built and makes build records large and slow to load (JENKINS-19022).

This option keeps only the entries for branches that match the branch specifiers of the current build, plus the branches of the current build. It is intended for jobs that build one branch, or a fixed set of branches, per build.

What changes:

  • With a parameterized branch specifier such as */${BRANCH}, the history of other branches is dropped. Polling compares against the default parameter value, so after each build of another branch the next poll schedules a build of the default branch. The changelog, GIT_PREVIOUS_COMMIT and GIT_PREVIOUS_SUCCESSFUL_COMMIT of a branch start fresh when it is built again after other branches.
  • With a wildcard specifier such as ** or */feature-* every built branch keeps matching, so the history still grows. This option does not help those jobs.
  • Only the default and ancestry build choosing strategies are affected; the history is kept unchanged for other strategies.
  • The option applies to the checkout it is configured on. When the same repository is checked out more than once in a build, enable it on each of those checkouts.
